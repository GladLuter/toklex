# Toklex

Toklex shrinks the replies of MCP tools. Most of a JSON reply is keys, quotes and whitespace, and the model pays for every token of it. Toklex sends a short schema once, through a tool named `toklex_schema`. After that each reply is a compact table with a one-line header such as `~ws@6425`. The header names the schema and its version. When the version changes, the model fetches the schema again.

The schema can also hold instructions from the server owner. A reply whose header carries `i:+` tells the model that those instructions apply. They travel with every reply, in every mode, so a safety rule is still in force when a caller switches compression off.

This repository holds the protocol ([spec/toklex.md](spec/toklex.md)), a PHP library, a conformance suite and an offline bench. Status is draft v0.1.

## Example

The schema is [examples/stations.schema.json](examples/stations.schema.json). The three records below are synthetic. The replies were produced by the PHP library with that schema and are not edited.

Pretty JSON, the usual reply:

```json
[
    {
        "station_id": "st-101",
        "name": "North Ridge",
        "terrain": "mountain",
        "network": "net_a",
        "wind_level": "MEDIUM",
        "rain_m": 0.0743,
        "snow_m": 0.0512,
        "hail_m": 0.0388
    },
    ...two more records like this
]
```

Safe mode:

```
~ws@6425 i:+ t:2026-09-30
id|n|c|p|l|v|u|d
st-101|North Ridge|mt|na|m|743|512|388
st-102|South Ridge|mt|na|m|751|498|401
st-103|Bay Point|co|nb|h|1534|120|905
```

Dense mode:

```
~ws@6425 i:+ t:2026-09-30
[3]
id:st-101|st-102|st-103
n:North Ridge|South Ridge|Bay Point
c:mt*2|co
p:na*2|nb
l:m*2|h
v:743|751|1534
u:512|498|120
d:388|401|905
```

`mt` is `mountain`, `m` is `MEDIUM`, and `743` is `0.0743` because the schema scales `rain_m` by 10000. `mt*2` means two equal cells in a row. The model learns all of this from the schema text.

## Modes

| Mode | What the reply is | Use it when |
|---|---|---|
| `safe` | A table. One line per record. | The default for most tools. |
| `dense` | One line per column, with runs (`m*2`) and date sequences (`2026-07-01+1d`). | Long result sets with repeated values and dates. |
| `off` | Compact JSON with full names and the instructions. | The model misreads codes, or you need plain output. |

A tool is safe by default. The schema lists the tools that are dense by default in `dense`.

Every tool gets an optional argument `toklex_mode` with the values `off`, `safe` and `dense`. The library removes it before your tool runs.

The tool `toklex_calibrate` checks which mode a model reads well. Without arguments it returns a small dataset in both forms and six questions. With `answers` it grades them and recommends a mode. The server keeps no state between the two calls.

## Numbers

These come from the offline bench in [bench/](bench/). The data is synthetic, generated by `bench/make_data.py` with seed 7 for five tools. Tokens are counted with o200k_base. The baseline is pretty JSON that includes the instruction notice.

| Mode | Tokens against the baseline |
|---|---|
| safe | -76% |
| dense | -88% |
| off | -33% |

A reading test with a small model (Claude Haiku) answered ten questions per mode, reading only the text. On this dataset one reader per mode scored 10 of 10 in safe, 10 of 10 in dense with every date right, and 8 of 10 in off. Earlier runs on data with the same shape scored 19 of 20 in safe, 19 of 20 in dense with the dates 8 of 8, and 10 of 10 in off. The misses were counts across many rows, a task small models find hard in any format.

Earlier research measured the tokenizer of Claude itself. A tree layout cost 1.6 times the tokens of a table. Dropping the row key from the table lost accuracy. Safe mode writes the record key in full on every record.

The bench is synthetic and the reading test used a small model. A production MCP server is being integrated, and its numbers will be added here when they exist.

To run the bench:

```
python bench/make_data.py
php bench/encode.php examples/stations.schema.json bench/out/enc
python bench/tokens.py
```

`bench/tokens.py` needs `pip install -r bench/requirements.txt`.

## Quick start for PHP

PHP 8.1 or newer. Copy `php/src/Toklex.php` into your project, or install with Composer as `toklex/toklex`.

```php
use Toklex\Toklex;

$tx = Toklex::fromFile(__DIR__ . '/stations.schema.json'); // throws InvalidArgumentException on a bad schema

// tools/list: adds the contract line and toklex_mode, appends the two Toklex tools
$tools = $tx->withTools($myTools);

// tools/call
switch ($name) {
    case Toklex::SCHEMA_TOOL:
        return $tx->schemaText();
    case Toklex::CALIBRATE_TOOL:
        return $tx->calibrate($args);
    default:
        $mode = $tx->mode($name, $args);   // removes toklex_mode from $args
        $rows = runMyTool($name, $args);   // a list of associative arrays
        return $tx->encode($name, $rows, ['date' => '2026-09-30'], $mode);
}
```

Return each reply as one MCP `text` content block and add no `structuredContent`.

Other methods:

- `$tx->error('nf', $mode)` encodes an error. It takes a code from `values.e` or the full message.
- `$tx->decode($reply)` reads a reply back into full names and values. Use it in tests.
- `$tx->version()` returns the schema version.
- `$tx->resources()` and `$tx->readResource($uri)` serve the two optional resources `toklex://modes` and `toklex://schema`.

`withTools` warns when a tool description goes over 2048 characters, because some clients cut it there and the contract line sits at the end.

## Writing a schema

A schema is one JSON file. `toklex` and `id` are required, the rest is optional.

```json
{
  "toklex": 1,
  "id": "ws",
  "keys": { "id": "station_id", "l": "wind_level", "v": "rain_m" },
  "values": { "l": { "l": "LOW", "m": "MEDIUM", "h": "HIGH" }, "e": { "nf": "No station with that id." } },
  "scale": { "v": 10000 },
  "instructions": { "rule": "Use only the fields in this reply." },
  "dense": ["station_history"]
}
```

- `id` is up to 8 characters, `[a-z][a-z0-9]{0,7}`.
- `keys` maps a short code to a field name. The codes `i` and `e` are taken by the header.
- `values` maps a field code to its value codes. The member `e` holds error messages.
- `scale` maps a field code to an integer of at least 10. A number travels as `x * scale`, rounded half away from zero, and the reader divides it back. Pick the precision you publish, as with DECIMAL(10,4).
- `instructions` holds named text blocks. All of them apply to a reply marked `i:+`.
- `dense` lists the tools that answer in dense mode by default.

The loader rejects codes that would be ambiguous in a cell, such as a code with a space, a `|` or a `*`, or one that looks like a number. A field name that is not in `keys` goes out as it is, so list any name that holds a `|`, a `:` or a space.

The version is the first four hex characters of the SHA-256 of the file, with CRLF turned into LF. Any edit changes it, a space included. A needless refetch costs a few tokens. An unnoticed change could make the model read codes wrongly.

## Porting to another language

[spec/toklex.md](spec/toklex.md) is the protocol. Appendix A holds every text the model sees, byte for byte. [spec/fixtures/](spec/fixtures/) is the conformance suite. It has 30 encode and decode cases, 15 schemas that must be rejected at load, a mode table and the version hash.

A port passes when it matches every fixture. For the PHP library:

```
php php/tests/run.php
```

The runner prints `OK <n> checks` and exits with 0, or lists the failures and exits with 1. It also compares the library output with Appendix A.
